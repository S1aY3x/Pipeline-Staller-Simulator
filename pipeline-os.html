          Pipeline Architecture

          Comprehensive reference for 5-Stage MIPS pipeline hazards and optimizations

          01

          5-Stage Pipeline

          The MIPS pipeline divides instruction execution into 5 independent stages that overlap in time, achieving near-CPI=1 throughput in ideal conditions.

          IF → ID → EX → MEM → WB
          IF — Instruction Fetch from instruction memory
          ID — Decode opcode, read register file
          EX — ALU computation, address calc
          MEM — Data memory read/write
          WB — Write result back to register file
          02

          Data Hazards (RAW)

          Read-After-Write hazards occur when an instruction tries to read a register before a previous instruction has written its result.

          stalls = max(0, 3 − distance)
          • Distance 1: 2 stalls without forwarding
          • Distance 2: 1 stall without forwarding
          • Distance 3+: No hazard
          • With forwarding: 0 stalls for most cases
          • Load-Use: always 1 stall even with forwarding
          03

          Control Hazards

          Branch instructions cause uncertainty in the instruction stream. The pipeline may fetch incorrect instructions before the branch outcome is known.

          • No prediction: 2-cycle penalty (stall until EX)
          • Predict not-taken: 1-cycle penalty if branch taken
          • Dynamic prediction: 0–1 cycle on misprediction
          • Flush = squash wrongly-fetched instructions
          04

          Data Forwarding

          Bypassing routes computed values directly from pipeline registers to where they're needed, without waiting for WB.

          • EX→EX: Result forwarded from EX/MEM latch
          • MEM→EX: Result forwarded from MEM/WB latch
          • Eliminates most data hazard stalls
          • Cannot forward loads before MEM completes
          05

          Structural Hazards

          Occur when two instructions need the same hardware resource at the same time.

          • MEM port conflict: LW/SW + IF share memory bus
          • Multiplier conflict: MUL/DIV take multiple cycles
          • Resolved by inserting pipeline stalls
          • Solution: Harvard arch (separate I$/D$)
          06

          Cache Hierarchy

          Cache misses introduce variable-latency stalls when data must be fetched from slower memory levels.

          • L1 hit: 1 cycle (no stall)
          • L1 miss → L2: 4–12 cycle penalty
          • L2 miss → DRAM: 50–200 cycle penalty
          • Replacement policies: LRU, FIFO, Random
